# Project_Description — учебное описание CalendarProject

Эта папка — твой «учебник» по собственному проекту. Каждый файл объясняет одну часть системы: как она устроена сейчас, на какие файлы и строки в коде смотреть, и что почитать про используемые технологии, чтобы дальше принимать осознанные решения.

Файлы намеренно «человеческие»: с прозой, картинками потоков в виде ASCII и блоком «что почитать» в конце. Они **не дублируют** [CLAUDE.md](../CLAUDE.md) — там короткая шпаргалка, а здесь объяснения.

## Как читать

1. Начни с [бэкенда](./Как%20работает%20бэкенд.md) — там общая карта проекта.
2. Дальше можно идти в любом порядке: про каждую часть есть отдельный файл.
3. Все ссылки на код — кликабельные `[путь:строка](../путь#Lстрока)`. Открываются прямо в VSCode.
4. Если строки «уехали» — проверь актуальность: `git log -L NN,NN+5:путь`.

## Стек одной таблицей

| Слой | Что используется | Зачем |
|---|---|---|
| Веб-фреймворк | FastAPI (ASGI) | Async, авто-валидация, OpenAPI «из коробки» |
| HTTP-сервер | uvicorn | ASGI-сервер с авто-перезапуском в dev |
| Шаблоны | Jinja2 | HTML-страницы, рендер на сервере |
| Стили | CSS вручную | Без Tailwind/Bootstrap, своя дизайн-система |
| Пароли | passlib + bcrypt | Хеширование с авто-распознаванием формата |
| Сессии | starlette `SessionMiddleware` | Подписанные cookie с `user_id` |
| API-токены | PyJWT (HS256) | Stateless-авторизация для `/api/v1/*` |
| Email-токены | itsdangerous | Подписанные одноразовые ссылки (verify, reset) |
| ORM | SQLAlchemy 2.0 (async) | Декларативные модели, `select()`-стиль |
| Драйвер БД | asyncpg | Async-доступ к PostgreSQL |
| Миграции | Alembic | Версионирование схемы, источник истины |
| Тесты | pytest + реальный Postgres | Без моков, чтобы не было «зелёных тестов на красной проде» |

## Как обновлять документацию

Когда меняется код — соответствующий md-файл может «протухнуть»: номера строк или имена функций сдвигаются. Простой способ обновить:

1. Найди в файле блок с устаревшей ссылкой.
2. Открой файл-источник, посмотри новую строку.
3. Поправь ссылку (`#L123` → новый номер).
4. Если поменялось поведение — обнови прозу рядом.

Идеально — после каждого крупного PR пробегаться по файлам в `Project_Description/` и подкручивать «уехавшее».
