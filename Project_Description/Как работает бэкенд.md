# Как работает бэкенд

## Краткая суть

Бэкенд — это асинхронное FastAPI-приложение, которое отвечает за две разные «аудитории»:

- **Браузер** — рендерит HTML-страницы через Jinja2 (роуты `/`, `/main`, `/task/...`, `/calendar` и т. п.). Сессия — в подписанной cookie.
- **API-клиенты** (мобилка, скрипты, Swagger) — получают JSON под префиксом `/api/v1/*`. Авторизация — JWT в заголовке `Authorization: Bearer ...` или та же cookie.

Один и тот же код в БД, та же модель пользователя, те же права. Разница только в том, что HTML-роуты на ошибку отвечают редиректом, а API — JSON 401.

## Карта проекта

```
запрос
  │
  ▼
┌──────────────────── app/main.py ────────────────────┐
│  FastAPI app + SessionMiddleware + StaticFiles      │
│  обработчики ошибок (RedirectToLogin → 303, 404)    │
└────────┬──────────────┬───────────────┬─────────────┘
         │              │               │
   HTML-роутеры     API-роутеры    /static/*
   app/routers/    app/routers/api/  (CSS, аватары)
         │              │
         ▼              ▼
   app/deps.py — get_current_user / get_current_user_api
         │
         ▼
   app/crud.py — все операции с БД (функции, async)
         │
         ▼
   app/models.py — ORM-модели (User, Task, TaskRole, …)
         │
         ▼
   app/database.py — async engine, SessionLocal
         │
         ▼
   PostgreSQL (через asyncpg)
```

## Точка входа: `app/main.py`

[app/main.py:15-20](../app/main.py#L15-L20) — создаём FastAPI-приложение. Включаем `/docs` (Swagger UI) и `/redoc`.

[app/main.py:21](../app/main.py#L21) — `SessionMiddleware` подписывает cookie `SECRET_KEY`'ом, TTL = 30 дней. Внутри сессии хранится один ключ — `user_id`.

[app/main.py:22](../app/main.py#L22) — отдаём папку `static/` по адресу `/static/...` (CSS, аватарки).

[app/main.py:24-27](../app/main.py#L24-L27) — подключаем четыре группы роутов:

```python
app.include_router(auth.router)    # / (логин), /registration, /verify-email, ...
app.include_router(tasks.router)   # /main, /create_task, /task/{id}, /calendar
app.include_router(users.router)   # /profile, /user/{id}, ...
app.include_router(api_router)     # /api/v1/* (auth, tasks, users)
```

[app/main.py:30-37](../app/main.py#L30-L37) — два глобальных обработчика ошибок:

- `RedirectToLogin` (наше кастомное исключение) → 303 на `/`. Бросают его HTML-роуты, когда юзер не залогинен.
- 404 → шаблон `not_found.html`.

[app/main.py:40-42](../app/main.py#L40-L42) — запуск uvicorn'а. В CLAUDE.md есть и команда вручную: `uvicorn app.main:app --reload --port 8080`.

## Слой конфигурации: `app/config.py`

Все «знания о среде» — здесь, читаются из `.env` через `python-dotenv` ([app/config.py:1-4](../app/config.py#L1-L4)).

Три полезных трюка:

1. **Авто-перевод sync URL'а в async** ([app/config.py:11-16](../app/config.py#L11-L16)): если в `.env` лежит `postgresql://...` или `postgresql+psycopg2://...`, мы прозрачно меняем драйвер на `asyncpg`. Это «спасательный жилет» от старых конфигов.
2. **Все TTL'ы в секундах** ([app/config.py:28-29](../app/config.py#L28-L29)): `VERIFY_TOKEN_TTL = 3 дня`, `RESET_TOKEN_TTL = 1 час`. Меняешь тут — меняется везде.
3. **`SQL_ECHO`** ([app/config.py:18](../app/config.py#L18)) — флаг, при котором SQLAlchemy печатает каждый SQL-запрос в консоль. Удобно для дебага, в проде выключаем.

## Слой подключения к БД: `app/database.py`

Файл маленький, но именно он задаёт «правила игры» для всех async-операций.

```python
engine = create_async_engine(DATABASE_URL, echo=SQL_ECHO)
SessionLocal = async_sessionmaker(
    bind=engine,
    class_=AsyncSession,
    autoflush=False,
    autocommit=False,
    expire_on_commit=False,
)
Base = declarative_base()

async def get_db():
    async with SessionLocal() as db:
        yield db
```

Что важно понимать:

- `expire_on_commit=False` ([app/database.py:12](../app/database.py#L12)) — после `commit()` объекты остаются «живыми», к ним можно обращаться без повторной загрузки. Без этого FastAPI бы регулярно падал при сериализации в JSON.
- `get_db()` — **dependency-injection** для FastAPI. Каждому HTTP-запросу даётся **своя** сессия, и она закрывается, когда запрос отрабатывает (`async with`). Подробнее — в файле «Как устроены ORM-модели и БД».

## DI-цепочка: `app/deps.py`

Чтобы роут получил «текущего пользователя», он подписывается:

```python
async def my_route(user: User = Depends(get_current_user), db = Depends(get_db)):
```

Двух функций (а не одной) — потому что HTML и API ведут себя по-разному при отсутствии авторизации:

- [app/deps.py:35-42](../app/deps.py#L35-L42) `get_current_user` — для HTML. Если юзера нет → бросает `RedirectToLogin` (что превратится в 303 на `/`).
- [app/deps.py:45-63](../app/deps.py#L45-L63) `get_current_user_api` — для `/api/v1/*`. Сначала смотрит JWT-токен в `Authorization`, потом cookie, иначе — `HTTPException(401)`.

Подробнее об этом — в «Как работает авторизация».

## Шаблоны: `app/templating.py`

[app/templating.py:31](../app/templating.py#L31) — единый объект `templates`, через который рендерятся все HTML-страницы:

```python
return templates.TemplateResponse(request, "main.html", {"user": user, "tasks": tasks})
```

Внутри один интересный приём — **cache-busting для статики** ([app/templating.py:17-28](../app/templating.py#L17-L28)). Когда в шаблоне пишут `url_for('static', filename='css/style.css')`, мы добавляем к ссылке `?v=<mtime файла>` — браузер сразу подхватывает свежий CSS, не упираясь в свой кэш.

Подробнее — в «Как устроены шаблоны и фронтенд».

## CRUD-слой: `app/crud.py`

Это **функциональный модуль** (не класс) с async-функциями над БД. Структура простая:

- `add_user`, `update_user`, `get_user_by_email`, ... — всё про юзеров
- `create_task`, `create_task_bundle`, `get_subtasks`, ... — всё про задачи
- `create_task_role`, `assign_user_to_task_role`, ... — всё про роли

Один пример «как это выглядит» ([app/crud.py:91-97](../app/crud.py#L91-L97)):

```python
async def get_user_by_id(db: AsyncSession, user_id: int) -> Optional[User]:
    return await db.get(User, user_id)


async def get_user_by_email(db: AsyncSession, email: str) -> Optional[User]:
    result = await db.execute(select(User).where(User.email == email))
    return result.scalar_one_or_none()
```

Главное правило: **все обращения к БД идут через crud.py**. Роуты не пишут SQL и не работают с сессией напрямую — это упрощает рефакторинг и тесты.

Особое место — `create_task_bundle` ([app/crud.py:129-151](../app/crud.py#L129-L151)): создаёт задачу + три роли (Тимлид/Менеджер/Разработчик) + права + назначает создателя Тимлидом. То есть «новый проект» — это не один insert, а целый бандл операций.

## Обработка ошибок

Стратегия минималистичная:

- Бизнес-ошибки в роутах → `HTTPException(status_code, detail)` (FastAPI сам превратит в JSON).
- Не залогинен на HTML-странице → `raise RedirectToLogin()` (главный обработчик в `main.py` его поймает).
- Не нашли страницу → 404 → `not_found.html`.

Никаких глобальных try/except — лишний шум, который только маскирует баги.

## Миграции

База — единственный источник истины, и за неё отвечает Alembic. Сейчас миграция одна:

- [alembic/versions/85155a07e605_baseline.py](../alembic/versions/85155a07e605_baseline.py) — создаёт все 6 таблиц (users, tasks, task_roles, task_role_permissions, task_user_roles, availability_slots).

Жёсткое правило: **никогда не использовать `Base.metadata.create_all()`**. Если меняешь модель — пиши миграцию (`alembic revision --autogenerate -m "..."`). Подробнее — в «Как устроены ORM-модели и БД».

## Точка запуска dev-сервера

Из CLAUDE.md:

```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8080
```

`--reload` следит за изменениями `.py` и сам перезапускает воркер. Для CSS/HTML перезапуск не нужен — Jinja и StaticFiles читают файлы каждый раз заново (плюс наш cache-bust).

## Технологии под капотом

### FastAPI
Современный Python веб-фреймворк, построенный на ASGI и `pydantic`. Главные плюсы — автоматическая валидация входных данных (по аннотациям типов), генерация OpenAPI/Swagger «бесплатно» и нативный async. Под капотом — **Starlette** (HTTP-инфраструктура) + **pydantic** (схемы данных).

### ASGI / uvicorn
ASGI — это «следующее поколение» WSGI: интерфейс между веб-сервером и Python-приложением, поддерживающий async и WebSocket. **uvicorn** — самая популярная реализация, на ней крутятся практически все FastAPI-приложения.

### SQLAlchemy 2.0 (async) + asyncpg
SQLAlchemy — Python ORM. Версия 2.0 принесла «новый стиль» (`select()`, `await db.execute()`) и лучший async-режим. **asyncpg** — это самый быстрый async-драйвер для Postgres, написанный на Cython, без блокирующих сокетов.

### Pydantic
Библиотека для описания и валидации структур данных через тип-аннотации. FastAPI на ней построен: ты пишешь `class TaskCreate(BaseModel): name: str`, и фреймворк сам проверяет входной JSON.

### Alembic
Инструмент миграций для SQLAlchemy. Хранит каждую версию схемы как Python-файл в `alembic/versions/`. Команды-минимум:

```bash
alembic revision --autogenerate -m "add column ..."
alembic upgrade head
alembic downgrade -1
```

### Jinja2
Движок шаблонов. Синтаксис — `{% if %}`, `{% for %}`, `{{ var }}`. Ставится в комплекте с FastAPI через `fastapi.templating.Jinja2Templates`.
