# Как устроены шаблоны и фронтенд

## Краткая суть

Фронтенд проекта — это **серверный рендер**: FastAPI на каждый запрос генерирует полную HTML-страницу и отправляет браузеру. Никакого React/Vue/Angular нет. Шаблонный движок — **Jinja2**. Стили написаны вручную, без Bootstrap/Tailwind, в одном файле `static/css/style.css`. JS — ванильный, вшит прямо в шаблоны, используется только для маленьких интерактивных деталей (дропдауны, вкладки).

Это проще в понимании, чем SPA, но рендер каждой страницы — это полный HTTP-запрос к серверу. Никакой «реактивности» или частичных обновлений без перезагрузки.

## Как FastAPI рендерит страницу

[app/templating.py:31](../app/templating.py#L31):

```python
templates = Jinja2Templates(directory="templates", context_processors=[_url_for_ctx])
```

Это глобальный объект, через который все роуты рендерят HTML. Вызов:

```python
return templates.TemplateResponse(request, "main.html", {"user": user, "tasks": tasks})
```

FastAPI-специфика: **обязательно передавать `request`** первым аргументом. Без него `url_for()` в шаблоне падает. Остальное — просто словарь контекста: любые Python-объекты, которые нужны шаблону.

## Структура типичного шаблона

Проект не использует `{% extends %}` с общим базовым шаблоном. Вместо этого — **`{% include %}`**: каждый шаблон полностью самодостаточен, но вставляет повторяющиеся блоки через include.

Пример структуры `task_overview.html` ([templates/task_overview.html:1-13](../templates/task_overview.html#L1-L13)):

```html
{% import "_icons.html" as icons %}
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Обзор — {{ task.name }}</title>
    <link href="{{ url_for('static', filename='css/style.css') }}" rel="stylesheet">
</head>
<body>
    <div class="container">
        {% include 'sidebar.html' %}          <!-- боковое меню -->
        <main class="main-content">
            ...
            {% include '_user_menu.html' %}   <!-- аватар + дропдаун -->
        </main>
    </div>
    <script>...</script>
</body>
```

### Jinja2-синтаксис: минимум что нужно знать

| Конструкция | Что делает |
|---|---|
| `{{ variable }}` | Вставить значение переменной (с auto-escaping) |
| `{% if condition %}...{% endif %}` | Условие |
| `{% for item in list %}...{% endfor %}` | Цикл |
| `{% include 'file.html' %}` | Вставить другой шаблон (с текущим контекстом) |
| `{% import 'file.html' as m %}` + `{{ m.macro() }}` | Импортировать макросы |
| `{% macro name(args) %}...{% endmacro %}` | Объявить многоразовый блок |
| `{{ loop.first }}`, `{{ loop.last }}`, `{{ loop.index }}` | Встроенные переменные цикла |
| `{{ value | default('') }}` | Фильтр: если `None` — подставить пустую строку |

Auto-escaping включён по умолчанию для HTML-шаблонов: `{{ "<script>" }}` превратится в `&lt;script&gt;`, а не вставится сырым HTML. Это защита от XSS.

### Макросы в `_icons.html`

[templates/_icons.html](../templates/_icons.html) содержит SVG-иконки как Jinja-макросы. Использование в шаблоне:

```html
{% import "_icons.html" as icons %}
{{ icons.chevron_right() }}
{{ icons.trash(color="red") }}
```

Плюс такого подхода: иконки не загружаются отдельными HTTP-запросами (как PNG-файлы), а встроены прямо в HTML. Изменить цвет — просто передать параметр в макрос.

## Кастомный `url_for` с cache-bust

Обычный FastAPI `url_for('static', path='css/style.css')` генерирует `http://127.0.0.1:8080/static/css/style.css`. Проблема: браузер агрессивно кешируют статику. Обновил CSS — браузер всё равно показывает старую версию.

Наше решение — [app/templating.py:17-28](../app/templating.py#L17-L28):

```python
def _url_for_ctx(request: Request):
    def _url_for(name: str, **kwargs):
        if name == "static" and "filename" in kwargs:
            filename = kwargs.pop("filename")
            url = request.url_for(name, path=filename)
            return f"{url}?v={_static_mtime(filename)}"   # ← добавляем ?v=<timestamp>
        return request.url_for(name, **kwargs)
    return {"url_for": _url_for}
```

`_static_mtime(filename)` читает `os.stat().st_mtime` файла в секундах. Итог: каждый раз, когда `style.css` меняется, URL превращается в `...?v=1714284721`, и браузер видит «другой» файл, сбрасывает кэш, скачивает заново.

Это передаётся в шаблоны через `context_processors=[_url_for_ctx]`. В шаблоне использование такое же, как всегда:

```html
<link href="{{ url_for('static', filename='css/style.css') }}" rel="stylesheet">
```

Разница прозрачна — шаблонер ничего не знает про cache-bust.

## Статика: `StaticFiles`

[app/main.py:22](../app/main.py#L22):

```python
app.mount("/static", StaticFiles(directory="static"), name="static")
```

Starlette `StaticFiles` — простой файловый сервер. Всё содержимое папки `static/` маппится на `/static/...`. Аватарка юзера по `avatar_url = "static/user_avatars/abc123.jpg"` будет доступна по `http://host/static/user_avatars/abc123.jpg`.

Папка `user_avatars/` создаётся автоматически при старте ([app/main.py:13](../app/main.py#L13)):

```python
os.makedirs(UPLOAD_FOLDER, exist_ok=True)
```

Важно: в продакшне статику обычно отдаёт nginx, а не Python-приложение (быстрее и экономнее). Но для dev всё работает через Starlette.

## CSS без фреймворков

Все стили — в одном файле [static/css/style.css](../static/css/style.css). Подход: **BEM-подобные классы**, без утилитарного CSS.

### Принципы дизайн-системы (Skolkovo light cream)

Дизайн «причёсывался» в коммитах L.1–L.2 (see `git log --oneline`). Главные идеи:

- Кремово-светлые фоны, без жёстких чёрных границ.
- `--primary`, `--surface`, `--border` и другие CSS-переменные для цветов.
- Скруглённые карточки, мягкие тени.
- Минималистичная типографика.

CSS-переменные позволяют менять всю палитру из одного места `:root { --primary: #...; }`.

### Структура CSS-файла (схематично)

```
:root { ... }              — CSS-переменные (цвета, размеры)
* { box-sizing: ... }      — глобальный reset
body, .container { ... }   — layout
.sidebar { ... }           — боковое меню
.main-content { ... }      — основной контент
.header { ... }            — шапка страницы
.btn-primary, .btn-secondary { ... }  — кнопки
.task-card { ... }         — карточка задачи на /main
.gantt-grid { ... }        — диаграмма Ганта (большая секция)
.tree { ... }              — иерархическое дерево
.calendar { ... }          — страница календаря
...
```

Никаких `@media` для адаптивности практически нет — проект рассчитан на desktop-браузер.

## Хлебные крошки

Большинство страниц содержит breadcrumb-блок прямо в HTML. Пример из [templates/task_overview.html:18-22](../templates/task_overview.html#L18-L22):

```html
<div class="breadcrumb">
    <a href="/main">Проекты</a>
     / <a href="/task/{{ task.id }}">{{ task.name }}</a>
     / Обзор
</div>
```

Хлебные крошки захардкожены в каждом шаблоне — нет универсальной системы генерации пути. Это просто и предсказуемо, но если поменяются URL'ы — нужно идти по каждому шаблону руками.

## JavaScript: минималистичный и ванильный

JS в проекте — это `<script>` в конце каждого шаблона. Никакого сборщика (webpack/vite), никаких npm-пакетов.

Типичный блок JS — переключение вкладок (из `task_overview.html`):

```javascript
const tabs = document.querySelectorAll('.overview-tab');
const panels = document.querySelectorAll('.overview-panel');
tabs.forEach(tab => {
    tab.addEventListener('click', () => {
        tabs.forEach(t => t.classList.remove('active'));
        panels.forEach(p => p.classList.remove('active'));
        tab.classList.add('active');
        document.querySelector(`.overview-panel[data-panel="${tab.dataset.tab}"]`)
            .classList.add('active');
    });
});
```

Ещё один частый паттерн — выпадающее меню юзера (в `_user_menu.html`):

```javascript
const btn = document.getElementById('userMenuButton');
const dd  = document.getElementById('userDropdown');
btn.addEventListener('click', e => { e.stopPropagation(); dd.classList.toggle('show'); });
document.addEventListener('click', () => dd.classList.remove('show'));
```

Принцип: **максимум на CSS** (hover, transitions, transforms), **минимум на JS** (только что CSS не умеет — toggling классов, закрытие дропдаунов по click-outside).

## Форма создания задачи

`create_task.html` — стандартная HTML-форма с `method="post"`:

```html
<form method="post" action="/create_task">
    <input name="taskName" type="text" required>
    <textarea name="taskDescription"></textarea>
    <input name="taskDeadline" type="datetime-local">
    <input name="taskColor" type="color" value="#0ea5e9">
    ...
    <button type="submit">Создать</button>
</form>
```

Данные идут как `application/x-www-form-urlencoded` → FastAPI принимает через `Form(...)`. Никакого AJAX. Если сервер нашёл ошибку — возвращает тот же шаблон с `{"error": "..."}` в контексте, Jinja его рендерит.

## Аватарки

При загрузке аватарки ([app/routers/users.py](../app/routers/users.py)):

1. Файл принимается через `UploadFile` в роуте.
2. Проверяется расширение (`ALLOWED_EXTENSIONS = {"png", "jpg", "jpeg", "gif"}`) и размер (`MAX_CONTENT_LENGTH = 16 MB`).
3. Сохраняется в `static/user_avatars/{user_id}_{filename}`.
4. Путь записывается в `user.avatar_url`.

В шаблонах:

```html
{% if user.avatar_url %}
<img src="{{ url_for('static', filename=user.avatar_url.replace('static/', '')) }}" ...>
{% else %}
<div class="avatar-placeholder">{{ user.name[0] }}</div>
{% endif %}
```

## Шаблон для служебных сообщений

`auth_message.html` — универсальная страница для статусных сообщений (подтверждение email, ошибка ссылки, ...). Роут передаёт `title` и `message` в контексте:

```python
return templates.TemplateResponse(request, "auth_message.html", {
    "title": "Почта подтверждена",
    "message": "Готово. Можешь пользоваться аккаунтом.",

```

Это хороший приём — не плодить шаблоны на каждый вид сообщения.

## Что НЕ реализовано

- **Нет базового шаблона** с `{% extends %}`. Каждый шаблон — полная страница. Плюс: независимость. Минус: изменить общий `<head>` нужно во всех файлах.
- **Нет JS-сборщика**. Нельзя использовать npm-пакеты. Если нужна зависимость (например, flatpickr для date-picker) — нужно подключить через CDN.
- **Нет адаптивной вёрстки**. Мобильный браузер покажет desktop-разметку.
- **CSS в одном файле**. При масштабировании проекта станет неудобно. Альтернатива — CSS Modules или разбивка на тематические файлы с `@import`.

## Технологии под капотом

### Jinja2
Шаблонный движок, пришедший из Flask. Синтаксис вдохновлён Django templates. Основные фичи: auto-escaping HTML, фильтры (`| upper`, `| default`), макросы, include/import. Рендеринг — синхронный: шаблон превращается в строку и отправляется в Response.

Jinja2 vs React/Vue: сервер владеет данными и рендеринг делает он. Плюсы — SEO, нет JavaScript-runtme, просто дебажить. Минусы — нет реактивности, каждое взаимодействие = HTTP-запрос.

### Server-Side Rendering (SSR)
Подход, при котором HTML генерируется на сервере. Противоположность — CSR (Client-Side Rendering), где браузер получает пустой `index.html` и JS сам строит страницу (React SPA). SSR быстрее первая загрузка (браузер сразу получает готовый HTML), лучше SEO.

### CSS Grid и Flexbox
**Flexbox** — одномерная раскладка (строка или колонка). Используется для навигации, кнопок, header'ов.
**CSS Grid** — двумерная (строки + колонки). Используется в диаграмме Ганта и в общем layout страницы (`sidebar + main-content`).

### CSS-переменные (custom properties)
Объявляются в `:root { --primary: #4f46e5; }`, используются как `color: var(--primary)`. Позволяют менять тему из одного места и легко кастомизировать отдельные компоненты.

### StaticFiles (Starlette)
Простой файловый сервер для Python-приложений. В проде обычно заменяется на nginx — он отдаёт статику гораздо быстрее (без Python overhead).

### Cache-busting через mtime
Классический приём: к URL статического файла добавляется уникальный суффикс (версия, хеш, timestamp). Браузер при изменении URL считает файл новым и скачивает заново. Реализации: `?v=timestamp`, `?hash=<md5>`, или «content-addressable filenames» типа `style.abc123.css` (последнее делают webpack/vite).
