## Целевая архитектура: гибрид SSR + JSON API

```
┌──────────────────────────────────────────────────────┐
│  Пользователь в браузере                             │
└──────────────┬─────────────────────────┬─────────────┘
               │ HTML + Jinja            │ JSON
               ▼                         ▼
┌──────────────────────┐   ┌──────────────────────────┐
│  HTML-роутеры        │   │  /api/v1/* (REST)        │
│  app/routers/        │   │  app/routers/api/        │
│  auth, tasks, users  │   │  Pydantic-схемы          │
└──────────────┬───────┘   └──────────────┬───────────┘
               │                          │
               ▼                          ▼
        ┌──────────────────────────────────────┐
        │  Общий слой бизнес-логики            │
        │  crud.py, permissions.py,            │
        │  visibility.py, security.py          │
        └──────────────┬───────────────────────┘
                       ▼
        ┌──────────────────────────────────────┐
        │  SQLAlchemy 2.0 async + asyncpg      │
        │  Alembic (источник истины схемы)     │
        └──────────────────────────────────────┘
```

**Принципы:**
- **Одна логика, два представления.** SSR-роуты и API-роуты вызывают один и тот же `crud.py` / `permissions.py`. Никакой дубль-логики.
- **Авторизация: cookie-сессии primary, JWT optional.** Cookie — для браузерных пользователей. JWT Bearer (`I`) — для будущих клиентов (мобилка, скрипты, интеграции). Оба механизма в `deps.py:get_current_user` через `try jwt → fallback session`.
- **Контракт API задокументирован.** `/docs` (Swagger) — источник правды для JSON. HTML-страницы документируются только в коде.
- **Alembic — единственный источник истины схемы БД.** `db.sql` оставляем как историческую справку, но не редактируем.

## Что фиксируем в текущем состоянии (НЕ меняем)

- Cookie-сессии остаются основным auth для HTML.
