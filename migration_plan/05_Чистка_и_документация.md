# Этап 5: Чистка legacy и документация

## Зачем

В проекте остались артефакты, которые путают новых разработчиков
(в том числе Claude в новой сессии). Цель — сделать репозиторий
самодокументируемым.

## Что нужно изучить

1. **README-driven development:** документация как часть API проекта.
2. **ADR (Architecture Decision Records):** короткие записи «почему сделано так».
3. **Twelve-Factor App** (для блока «деплой» в README).

## Подэтапы

1. **Пометить `db.sql` как deprecated:**
   ```sql
   -- DEPRECATED: исторический snapshot схемы.
   -- Источник истины — alembic/versions/. Не редактировать этот файл.
   ```

2. **Обновить TODO.md:**
   - Удалить устаревшие пункты (1, 5 — уже сделаны).
   - Перенести актуальные в issues или в этот план.

3. **Расширить README.md:**
   - Секция «Архитектура» — короткая ссылка на `migration_plan/00_Цели_и_архитектура.md`.
   - Секция «Деплой» — переменные окружения для production (SECRET_KEY, DATABASE_URL, EMAIL_*).
   - Секция «Структура API» — ссылка на `/docs`.

4. **ADR в `docs/adr/`:**
   - `001-hybrid-ssr-and-json-api.md` — почему гибрид, а не чистый REST.
   - `002-cookie-primary-jwt-fallback.md` — почему cookies primary.
   - `003-alembic-source-of-truth.md` — почему `db.sql` deprecated.

5. **Обновить CLAUDE.md** под новую целевую архитектуру:
   - Добавить ссылку на `migration_plan/00_Цели_и_архитектура.md`.
   - В «Gotchas» добавить пункты про CSRF (после Этапа 2) и parity-тесты (после Этапа 1).

6. **Финальный аудит CSS:**
   - Этап L.1 уже почистил мёртвые классы. Закрепить: `stylelint` или скрипт, проверяющий что все классы из CSS встречаются в шаблонах.

## Критерий завершения

- README покрывает: запуск, тесты, деплой, ссылки на доки.
- Есть `docs/adr/` с минимум 3 записями.
- CLAUDE.md актуален.
- `db.sql` помечен.
