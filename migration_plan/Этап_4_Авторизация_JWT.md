# Этап 4: Авторизация JWT Токены вместо Куки

## Зачем нужен этот этап?
`flask_login` использовал сессии в куки браузера. Это плохо подходит для REST API, которым могут пользоваться мобильные приложения. Мы переходим на токены (JWT - JSON Web Token). При входе пользователь получает строку (токен) и прикрепляет её к каждому следующему запросу.

## Что нужно изучить (Технологии):
1. **Как работает JWT:** Структура токена (Header, Payload, Signature) и зачем нужен секретный ключ.
2. **OAuth2 Password Bearer:** Стандартная схема авторизации в FastAPI.
3. **Хэширование паролей:** Библиотека `passlib` и алгоритм bcrypt (почему пароли нельзя хранить в открытом виде).

## Подэтапы (Как будем реализовывать):
1. **Безопасность (security.py):**
   Напишем функции `get_password_hash` и `verify_password` для проверки паролей.
2. **Генерация токена:**
   Напишем функцию `create_access_token`, которая берет ID пользователя, зашифровывает его с помощью секретного ключа и задает время жизни (например, 30 минут).
3. **Зависимость get_current_user:**
   Напишем функцию, которая читает заголовок `Authorization` в запросе, расшифровывает токен, лезет в БД и возвращает объект текущего пользователя.
