# Этап 4: Покрытие тестами и контроль качества

## Зачем

Сейчас 711 строк тестов на ~4000 строк кода (~18%). Для проекта с гибридной
архитектурой этого мало: легко получить regression в HTML-ветке при правке
сервисного слоя. CI уже есть (этап H), нужно сделать его «строгим».

## Что нужно изучить

1. **pytest-cov:** измерение покрытия и пороги.
2. **Контрактные тесты для Pydantic-схем:** OpenAPI snapshot.
3. **Линтеры:** ruff + mypy (опционально) в CI.

## Подэтапы

1. **Базовое покрытие до 70%:**
   - `pytest --cov=app --cov-report=term-missing --cov-fail-under=70` в CI.
   - Дописать тесты на: privacy-фильтрацию, RBAC permissions, email-флоу (verify + reset), pagination, overdue-статус.

2. **HTML smoke-тесты.** Сейчас тестов на HTML-роуты нет. Добавить:
   - GET всех страниц после логина → 200, есть ключевой текст.
   - POST форм (создание задачи, смена пароля) → 303 redirect или валидационная ошибка с понятным текстом.

3. **OpenAPI snapshot:**
   - `tests/test_openapi_snapshot.py`: сериализуем `app.openapi()` в JSON, сравниваем с эталоном `tests/openapi.snapshot.json`.
   - Любое изменение контракта API ломает тест → требует явного обновления snapshot.

4. **Линтеры в CI:**
   - `ruff check app/ tests/` — как обязательный шаг.
   - `ruff format --check` — единый стиль.
   - mypy — позже, опционально (большая работа по типам).

5. **E2E через Playwright (опционально):**
   - 2-3 ключевых флоу: регистрация → логин → создание задачи → смена состояния.
   - Запускается локально + ночной CI-job (медленный).

## Критерий завершения

- CI красный, если покрытие <70% или линтер ругается.
- OpenAPI snapshot хранится в репо.
- HTML-роуты покрыты smoke-тестами.
