# Этап 3: Строгая валидация данных (Pydantic)

## Зачем нужен этот этап?
Во Flask вы принимали данные через `request.form` и верили, что клиент прислал правильные поля. В REST API (JSON) мы используем строгие схемы. Если клиент забудет передать пароль при регистрации, FastAPI сам вернет красивую ошибку 422 (Unprocessable Entity) еще до того, как запрос дойдет до нашего кода. Этим управляет библиотека Pydantic.

## Что нужно изучить (Технологии):
1. **Pydantic v2:** Библиотека для валидации данных в Python. Базовый класс `BaseModel`.
2. **Сериализация данных:** Как объекты БД превращаются в JSON. Параметр `from_attributes=True` в Pydantic (раньше назывался `orm_mode`).

## Подэтапы (Как будем реализовывать):
1. **Схемы для Пользователя (schemas.py):**
   Создадим классы:
   * `UserCreate` (логин, пароль, email — для регистрации)
   * `UserResponse` (id, логин, email — то, что отдаем наружу, БЕЗ пароля).
2. **Схемы для Задач (schemas.py):**
   Создадим `TaskCreate` и `TaskResponse`. В ответе задачи нужно будет возвращать информацию о родительских/дочерних задачах.
3. **Привязка к SQLAlchemy:**
   Настроим схемы так, чтобы они могли автоматически "читать" данные из объектов базы данных.
